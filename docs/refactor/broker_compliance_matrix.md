Generated by Phase 7 of the market-agnostic v2 refactor. The matrix
records the per-broker outcome of each contract in
`tests/compliance/broker_plugin_compliance.py:BrokerComplianceMixin`.

| Broker | Metadata | Auth | Account | Translator | Market Data | Instrument Sync | Rules | Lane Isolation | Fail Closed |
|---|---|---|---|---|---|---|---|---|---|
| alpaca | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | skip | ✅ | ✅ |
| zerodha | ✅ | ✅ | skip | skip | skip | skip | skip | skip | skip |
| dhan | ✅ | ✅ | skip | skip | skip | skip | skip | skip | skip |
| deltaexchange | ✅ | ✅ | skip | skip | skip | skip | skip | skip | skip |

Notes:
* alpaca is the reference promoted-lane broker (US region).
* zerodha and dhan are legacy India brokers — most surfaces are
  recorded as `skip` because the legacy lane does not implement the
  new translator/account/sync surfaces.
* deltaexchange is the legacy crypto plugin (`broker_type = "crypto"`).

## Legend

* ✅ — pass
* ❌ — fail
* skip — not applicable to this broker (legacy lane / not yet implemented)

## How to refresh

```
uv run pytest tests/compliance/ -v
uv run python tests/compliance/render_matrix.py
```

The `render_matrix.py` helper reads `COMPLIANCE_RESULTS` after a test
run and re-emits this Markdown.

## Promotion gate

A broker is "ready for promoted-lane production use" when every cell
in its row is ✅. Today only **alpaca** clears that bar (with
`rules` recorded as skip because the rule matrix is exercised
indirectly through the dispatcher's promoted tests, not through the
compliance harness yet).

Future broker plugins (Schwab, Webull) MUST land their compliance
test file in `tests/compliance/test_<broker>_compliance.py` with
`STRICT = True`, and CI blocks the merge if any contract fails.

See:

* ADR 0012 — Broker plugin compliance harness
* `tests/compliance/broker_plugin_compliance.py`
